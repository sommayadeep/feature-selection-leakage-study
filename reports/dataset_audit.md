# Dataset Audit

## Scope

This audit was performed from the local files only. No data was uploaded to
external services and no experiment was run. File hashes are included to make
the inspected inputs identifiable.

## File integrity and orientation

| File | Shape | SHA-256 |
|---|---:|---|
| `data/raw/leukemia_big.csv` | 7,129 rows x 72 columns | `35e84928da625da0787efb31a451dedbdf390e821a94ef74b7b7ab6cab9466d4` |
| `data/processed/leukemia.csv` | 72 rows x 7,129 columns | `21ea525a9a66b19945d2f7d2788c9d83373eaafd4ffdafe00a3f959a6b677fce` |

The raw file has no header row. Its first row contains the 72 class labels and
the remaining 7,128 rows contain numeric measurements. The preparation script
transposes this matrix and writes the processed sample-by-feature table. The
processed file has one `target` column and 7,128 feature columns.

The prepared dimensions and labels agree with the assertions in
`src/prepare_leukemia.py`:

- 72 observations/patients.
- 7,128 candidate features.
- Two classes: `ALL` and `AML`.
- Class distribution: 47 `ALL`, 25 `AML`.
- The processed labels exactly match the raw first row.
- The processed feature count exactly matches the raw measurement rows.

## Values, types, and missingness

- All 7,128 feature columns are numeric `float64`.
- The target is a string column.
- Total missing values: 0.
- Missing feature values: 0.
- Missing target labels: 0.
- All feature values are finite.
- Observed feature range: -3.526672849 to 3.807687938.

The current absence of missing values means that the existing imputation steps
do not change the current matrix. It does not remove the need to fit imputation
inside training folds for a reusable pipeline or for future datasets.

## Duplicate and low-variation checks

The local processed data was checked without changing it:

- Duplicate complete observations: 0.
- Duplicate feature-only observations: 0.
- Duplicate feature columns: 0.
- Constant features: 0.
- Features with at most two distinct values: 0.

These checks do not establish that the samples are independent clinical
patients. The file does not contain patient identifiers, collection batches,
family/group information, or other metadata needed to check related samples or
batch leakage.

## Identifiers and biological interpretation

The processed feature names are synthetic names from `gene_0001` through
`gene_7128`. They are positional labels generated by
`src/prepare_leukemia.py`, not verified gene symbols, accession numbers, or
probe identifiers. No mapping file or source citation is present in the
workspace.

Consequently:

- The features can be used as anonymized/positional predictors in a
  methodological experiment.
- Individual selected features must not be described as biologically meaningful
  genes.
- Gene function, pathway, clinical, or patient-level claims cannot be made
  from the current files.
- A biological interpretation would require the original data provenance and a
  verified feature-identifier mapping.

## Target leakage and identifier review

The processed schema contains only the synthetic feature columns and `target`;
there is no explicit patient ID, split column, or named clinical covariate.
That is a positive schema property, but it is not proof that target-correlated
technical artifacts are absent. Without provenance, sample metadata, and the
original feature identifiers, technical or batch leakage cannot be ruled out.

The target is not included as a feature by the current preparation and
experiment scripts. The raw and processed files are internally consistent.

## Dataset limitations

The project has a small-sample, high-dimensional design: 72 observations and
7,128 features. The minority class has 25 observations, so estimates from
three-fold repeated cross-validation are necessarily noisy and folds are
dependent across repeats. High scores should not be treated as evidence of
clinical utility or external validity.

Only one dataset is present. There is no external dataset or independent
validation cohort in the workspace.

## Required follow-up

Before final scientific claims:

1. Record the authoritative dataset source, provenance, licensing, and
   preprocessing history.
2. Obtain and validate a reliable feature-identifier mapping if biological
   interpretation is desired.
3. Check patient-level grouping, related samples, batch variables, and
   duplicate/near-duplicate samples when metadata becomes available.
4. Keep any additional dataset clearly separate rather than silently replacing
   this dataset.
